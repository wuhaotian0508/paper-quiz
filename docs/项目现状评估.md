## 一、项目概览

| 项         | 内容                                                                    |
| ---------- | ----------------------------------------------------------------------- |
| 定位       | 把课程 PDF / 讲课录音变成可练习的小测 + 个性化复习单                    |
| 框架       | Next.js 15 App Router、React 19、TypeScript                             |
| AI         | OpenAI Responses API（结构化输出 + Zod 校验）、音频转写                 |

| 测试       | Vitest + Testing Library，59 个测试文件、246 个用例                     |

| 代码规模   | 约 11.4k 行（组件 + lib + 路由，含测试）                                |

## 二、目前已实现的功能

### 1. 上传与题目生成

- 支持 **PDF（最多 5 份合并为一个学习集）**、MP3 / M4A / WAV / WebM / MP4 录音，支持拖拽。
- 录音先走 `/api/transcribe` 转写，用户确认或修改 transcript 后再出题。
- 四类题型可分别指定数量（合计上限 15）：选择题、填空题、简答题、**自定义题型**（自填名称与出题要求）。
- 三档难度：基础回顾 / 综合练习 / 挑战模式。
- 题目重复时自动请求一次替换题（`lib/quiz-coverage.ts`）。
- 输出统一为英文，即使原材料是中文。

### 2. 答题与评分

- 一页一题（`components/quiz-view.tsx`）。
- 选择题、填空题**在浏览器本地判分**，不消耗 API、且材料失效后仍可用。
- 简答题与自定义题由 `/api/grade-answer` 结合原始材料评分，返回得分、反馈、缺失要点。
- 每题可就该题追问（`/api/question-chat`），回答被约束在材料范围内。
- **PDF 只上传一次**：`/api/generate-quiz` 通过 Files API 上传并返回 `sourceFileId`，后续评分和追问只传 id（`lib/source-reference.ts`）。网关不支持 Files API 时自动回退为内联发送。

### 3. 复习与回顾体系

- **错题本**：按题型筛选、批量选择、再次练习、导出 PDF、清空。
- **AI 知识点复习单**（`/api/generate-exam-review`）：从 PDF / transcript / 已保存题目中提炼核心概念、常见混淆、公式流程，并结合个人错题生成"你的重点"。结果存 localStorage，最多 40 份。
- **源页面回溯**：浏览器本地用 pdf.js 渲染 PDF 前 60 页为图片存进 IndexedDB，复习单每个知识点可点开对应页的预览图 / 灯箱 / 直接跳转 PDF 该页。
- **PDF 库**：每份上传的 PDF 成为持久库项（`lib/study-library.ts`），侧边栏"Your Library"和 Review Sheets 文档卡片展示掌握度、错题数、最近练习时间。
- **材料详情页**：按 PDF 聚合所有生成过的练习集、全部题目、全部错题。
- **历史与进度**：正确率趋势、练习日历、只读复盘、导出进度 PDF、从上传页恢复未做完的练习。

### 4. 分享

- **挑战链接** `/challenge/[slug]`：分享题目本身，7 天过期，不含源文件。
- **复习单链接** `/review/[slug]`：分享只读复习单，7 天过期。
- 两者都通过 Supabase `security definer` RPC 写入，带 slug 格式校验、过期校验、RLS。

### 5. 账号、同步与辅助

- `/login` 独立登录页；未登录访问 `/` 由 `app/page.tsx` 重定向。
- 跨设备同步练习会话与错题本（`hooks/use-study-sync.ts`），本地优先、快照 diff 上传，避免旧标签页覆盖新设备的编辑；换账号不会继承上一个账号的数据。
- **产品帮助 chatbot**（`/api/product-help`）：常驻的产品使用问答，知道当前所在界面。
- 帮助中心页、Google 表单反馈入口、亮/暗色主题切换。

## 三、存在的问题

### 🔴 高危：安全与成本

**1. 所有 API 路由完全没有鉴权。**
`app/page.tsx:18` 只保护了页面渲染，仓库里**没有 `middleware.ts`**，`/api/generate-quiz`、`/api/grade-answer`、`/api/question-chat`、`/api/transcribe`、`/api/generate-exam-review`、`/api/product-help` 全部可以被任意匿名请求直接 POST。任何人拿到域名就能白嫖你的 OpenAI 额度，且 README 明确写了"不再设置文件大小或 API 调用次数额度"。**这是当前最紧急的问题。**

**2. Blob 上传授权不校验用户。**
`app/api/study-upload/route.ts:10` 的 `onBeforeGenerateToken` 直接返回允许，没有任何身份检查 —— 任何人都能往你的 Vercel Blob store 写文件。

**3. 没有任何速率限制或配额。**
单次生成 15 道题 + 5 份 PDF + 逐题追问，成本上限完全不可控。

**4. 跨用户 `fileId` 引用风险。**
`lib/source-reference.ts:9` 只用正则 `^file[-_][A-Za-z0-9_-]{4,128}$` 校验格式，**不校验归属**。所有用户共用同一个 OpenAI API Key，若某个 file id 泄露或被猜中，在 7 天 TTL 内任何人都能把它塞进 `/api/grade-answer` 或 `/api/question-chat`，让模型读出别人 PDF 的内容。

### 🟠 功能缺陷（有实现但走不通 / 行为不一致）

**5. 分享复习单的源页面存了却永远读不出来。**
`lib/shared-review-client.ts` 会把 `sourcePages`（base64 JPEG data URL）一起写进 RPC，但 `supabase/migrations/20260804000000_shared_review_sheets.sql` 的 `get_shared_review_sheet` 只返回 `slug / title / topics / expiresAt`，**从不返回 `sourcePages`**。于是 `components/shared-review-view.tsx:70` 的整段渲染分支是死代码。
更糟的是这些图片仍然被写进了 jsonb 列 —— 几十张页面截图就是几 MB 塞进一行，白白撑大数据库和 PostgREST 负载。

**6. 隐私文案自相矛盾。**
`components/material-detail-view.tsx:396` 写的是 "Review notes only; the PDF and private mistakes stay private."，但代码实际把 PDF 页面截图提交了上去；`components/shared-review-view.tsx:61` 又写 "shares review notes and selected page previews"。两处说法冲突，且前者对用户是误导。

**7. Review Sheets 页面有三个死控件。**
`components/review-library.tsx:38` 的排序 `<select>` 是非受控的 `defaultValue` 且没有 `onChange`；网格 / 列表切换是纯装饰性的 `<span>`；卡片右上角的 `⋮` 菜单按钮没有任何行为。

**8. 侧边栏两个导航项指向同一个界面。**
`components/quiz-workspace.tsx:123` 中 `#dashboard` 和 `#quiz-lab` 都映射到 `upload` 视图，"Dashboard" 和 "Quiz Lab" 在体验上是同一页。

**9. 库状态有两份来源。**
`components/dashboard-navigation.tsx:52-78` 自己读 localStorage 并回写，`QuizWorkspace` 也维护同一份 `library` state，靠自定义事件同步。任何一侧改动逻辑都容易出现不一致。

**10. materialId 的取值不可靠。**
`lib/study-history.ts:39-41` 用 `${file.name}::${file.size}` 作为材料身份 —— 改个文件名就变成另一份材料（历史断裂），同名同大小的不同文件则会被错误合并。

**11. 全站用 hash 路由而非真实路由。**
`#mistake-book`、`#progress`、`#review-sheets` 等都是 hash + 事件驱动，浏览器后退键行为不符合直觉，无法分享或书签到具体子页面。

### 🟡 存储与性能

**12. 浏览器本地存储只增不减。**
`lib/source-pages.ts` 每份 PDF 最多存 60 页 JPEG data URL **加上原始 PDF blob** 到 IndexedDB，没有任何淘汰、过期或清理策略。多传几份大 PDF 就会撑爆浏览器配额。

**13. localStorage 写入静默失败。**
`lib/request-validation.ts:84-95` 的 `safeStorageSet` 捕获异常后返回 `false`，但**所有调用方都忽略了返回值**。配额满时用户的练习记录会在毫无提示的情况下丢失。

**14. 首屏体积与样式文件偏大。**
`/` 首屏 181 kB / First Load JS 336 kB；`app/globals.css` 是 **3666 行的单文件**，没有拆分。

**15. AI 请求全部非流式返回前端。**
服务端虽然用了 stream 但 `collectResponse` 后一次性返回，前端只有一个 LoadingView，用户在 60 秒内看不到任何进度。长材料 + 15 题很容易撞到 `maxDuration = 60` 上限。

### 🟡 同步能力的边界

**16. 同步只覆盖会话和错题。**
`hooks/use-study-sync.ts` 只同步 `paper_quiz_sessions` 和 `paper_quiz_mistakes`。**PDF 库、已保存的复习单、页面预览、原始 PDF 全部只在本地** —— 用户换电脑后 Review Sheets 页面是空的，这与"每份 PDF 都有自己的库"的产品叙事矛盾。

**17. 换设备后简答题无法评分。**
同步时刻意剥离了 `fileId`（`withoutDeviceFileReferences`），这是正确的安全设计，但用户侧的体验是"在另一台电脑上打开历史练习，简答题突然不能评分了"，目前没有引导性的提示或一键重传流程。

### 🟡 代码质量与工程

**18. 两个巨型组件已到重构临界点。**
`components/quiz-workspace.tsx` 738 行、20+ 个 `useState`、管理 14 种视图；`components/material-detail-view.tsx` 602 行、10 个 `useState`、同时负责复习单生成 / 分享 / PDF 附加 / 页面预览 / 灯箱 / 题目列表 / 错题列表。

**19. 测试有明显盲区。**
246 个用例全绿是很扎实的基础，但：没有任何 E2E（Playwright 插件已可用）；没有鉴权 / 限流的测试（因为功能本身不存在）；`app/api/study-upload/route.ts` 完全没有测试；SQL 迁移的 `*.test.ts` 只是对 SQL 文本做字符串断言，不连真实数据库 —— 第 5 条那种"存了读不出来"的缺陷正是这类测试抓不到的。

**20. 大量工作未提交。**
22 个已修改文件 + 14 个未跟踪文件（含新的 `lib/study-library.ts`、`lib/source-pages.ts`、`lib/saved-exam-review.ts`、`components/review-library.tsx` 和一个新的 SQL 迁移）尚未提交。根目录还散落着一张未跟踪的 `3c0f52e6725b905865a323774fd79149.png`。

**21. 文档与实现已有偏差。**
README 的"当前能力"仍写"单个 PDF"，代码已支持最多 5 份；默认模型 `gpt-5.6-luna`（`lib/openai-config.ts`）需要确认是否为线上实际使用的值。

## 四、后续改进建议

### 第一优先级：先把成本和数据风险堵上（建议本周内）

1. **加 `middleware.ts` 或在每个 API 路由头部做 Supabase 会话校验**，未登录一律 401。这是一行行改的小工作量，但收益最大。
2. **`/api/study-upload` 的 `onBeforeGenerateToken` 里校验用户**，并把 `pathname` 绑定到 `user.id` 前缀。
3. **加按用户的速率限制与日配额**（Upstash Redis 或 Supabase 一张计数表都可以），至少覆盖 `generate-quiz` / `generate-exam-review` / `transcribe` 三个贵的路由。
4. **把 `fileId` 与用户绑定**：生成时把 `(user_id, file_id, material_id)` 写一张表，评分和追问前先校验归属，而不是只校验字符串格式。

### 第二优先级：修掉已知的功能缺陷（1～2 周）

5. **修复分享复习单的源页面**：要么在 `get_shared_review_sheet` 里返回 `sourcePages`，要么就别再往 jsonb 里写图片。若决定保留该功能，**页面图片应该走 Vercel Blob 存 URL，而不是 base64 塞进数据库**。
6. **统一隐私文案**，让 UI 上写的和实际提交的内容完全一致，并在分享前明确告知"将附带 N 张源页面截图"。
7. **补齐 Review Sheets 页的三个死控件**（排序真正生效、网格/列表切换、卡片菜单），或者干脆先删掉，避免用户点了没反应。
8. **合并 Dashboard / Quiz Lab 两个导航项**，或让 Dashboard 成为真正的总览页（今日任务 + 最近复习单 + 待复习错题）。
9. **把 materialId 换成内容哈希**（读前若干 KB 做 SHA-256），彻底解决改名和重名问题。

### 第三优先级：体验与架构（1 个月内）

10. **改成真实路由**：`/library`、`/mistakes`、`/progress`、`/material/[id]`，用 App Router 而不是 hash。顺带解决后退键和可分享性。
11. **流式返回生成结果**，让用户在 5 秒内看到第一道题的雏形，同时把 `maxDuration` 提到 300 秒（Vercel 现已默认支持）。
12. **给本地存储加配额管理**：IndexedDB 页面预览设 LRU 上限、`safeStorageSet` 失败时给用户明确提示并提供"导出后清理"入口。
13. **拆分 `quiz-workspace.tsx`**：把视图路由、同步、库管理各自抽成 hook 或 context；`material-detail-view.tsx` 至少拆出"复习单区块"和"题目/错题列表"两个子组件。
14. **拆分 `globals.css`**：按模块拆成多个文件，或引入 CSS Modules / Tailwind。

### 第四优先级：产品能力扩展

15. **把库和复习单也纳入同步**（新增 `paper_quiz_library`、`paper_quiz_reviews` 两张表），让"换设备"这件事真正无缝。
16. **PDF 原件走 Blob 持久化**（用户可选），解决"7 天后简答题不能评分"的根本问题。
17. **补 E2E 测试**：至少覆盖"登录 → 上传 PDF → 生成 → 答题 → 进错题本 → 生成复习单 → 分享"这条主链路。
18. **加真实数据库的迁移测试**（本地 Supabase + `supabase db reset`），避免再出现第 5 条那种 SQL 与前端约定不一致的问题。
19. **补齐运营向能力**：错题的间隔重复排程、按知识点的掌握度雷达图、复习单的多份合并导出。

## 五、总体判断

这个项目的**工程底子相当扎实**：246 个测试全绿、类型和 lint 零告警、构建通过，几乎每个 lib 模块都有配套测试，关键设计决策（PDF 只上传一次、本地优先同步、快照 diff 防覆盖、分享时剥离私有字段）都写了注释说明理由，`docs/superpowers/` 下还留有 13 份设计文档和 12 份实施计划。这在同类个人项目里是少见的。

真正的短板集中在两处：

1. **服务端没有任何访问控制** —— 从"能跑的 demo"到"能上线的产品"，这是唯一的硬门槛。
2. **最近三周新加的功能（PDF 库、源页面回溯、复习单分享）跑得比验证快** —— 分享源页面存了读不出来、UI 上有死控件、隐私文案与行为不符，都是同一类症状：功能拼上去了但端到端没走通一遍。

建议的节奏是：**先花两三天把鉴权和限流补上**（第一优先级 4 项），**再花一周把已经写了但没跑通的功能收口**（第二优先级 5 项），之后再谈架构重构和新功能。
