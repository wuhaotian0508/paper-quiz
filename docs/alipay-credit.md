# 支付宝充值（个人收款码，演示用）

除了 Stripe 收银台，「设置」面板里还有一条支付宝通道：直接展示一张**个人收款码**，学习者扫码把钱付到收款人的支付宝，然后自己点「我已支付」，余额就记上一笔。

**这条路只适合演示。** 支付宝个人收款码没有商户号、没有 API、没有异步通知，程序完全无从核对这笔钱到底有没有到账——记账的唯一依据是那个按钮。放出来的前提是：练习本身免费且不限量，余额目前只显示、不扣减，所以就算有人空点按钮，也不会因此拿到任何东西。真要开始计费，这条路必须先换掉（见文末）。

## 钱是怎么变成余额的

1. `GET /api/alipay`：读 `ALIPAY_QR_URL`，在服务端把它渲染成二维码 PNG（`qrcode`，data URL）返回。没配这个变量就返回 503，面板里那个按钮点了会说「未配置」，不会画一个空框。
2. 学习者用支付宝扫码。**收款码本身不带金额**，所以界面明确提示要自己输入。面板上的 ¥14 / ¥35 / ¥70 只是填字的快捷键，旁边的输入框才是真正的入口 —— 通用码本来就能付任意金额，只给三档反而记不准。
3. `POST /api/alipay`：金额从请求体里取（`rmb`，人民币）。这跟 Stripe 那条路相反，是有意的：收款码不带金额，钱数是付款人在支付宝里自己敲的，服务端根本没有一个可供比对的数。能做的是挡掉压根不可能的数 —— `rmbToCents()` 拒绝空值、非数字、零、负数和超过 ¥500 的（静态码单日限额），再按固定汇率 7 折成美分。用户 id 仍然从会话 Cookie 取，未登录 401。然后用 service role 往 `paper_quiz_credit_entries` 写一条正数账目，并把求和后的新余额一起返回。
4. 面板直接用返回的余额刷新显示，不再二次读 `GET /api/credit`——刚写完的行未必立刻读得到。

## 和 Stripe 那条路的区别

|            | Stripe 收银台                          | 支付宝收款码                       |
| ---------- | -------------------------------------- | ---------------------------------- |
| 谁说钱到了 | Stripe webhook（验签后）               | 学习者点按钮                       |
| 幂等       | `stripe_event_id` 唯一索引挡住重复投递 | 每次点击都是新的一行，挡不住重复点 |
| 退款       | `refund.created` 自动记负数            | 无，只能手工改库                   |
| 金额来源   | 服务端固定价目表，请求体报价不采信     | 请求体，仅校验区间（¥1–¥500）      |
| 钱最终落到 | Stripe 余额，再由 Stripe 打款到银行卡  | 收款人的个人支付宝                 |

账本表是同一张。支付宝那条路没有 Stripe 事件可写，就自己造一个 id 填进 `stripe_event_id`（`not null unique`），前缀 `alipay_manual_`，在表里一眼能认出来——见 `lib/alipay.ts` 的 `alipayEventId()`。

## 需要的环境变量

| 变量            | 用途                                                                             |
| --------------- | -------------------------------------------------------------------------------- |
| `ALIPAY_QR_URL` | 个人收款码背后的链接，形如 `https://qr.alipay.com/xxxxxxxx`。留空 = 关闭这条路。 |

拿到这个链接的办法：支付宝 App →「收钱」→ 右上角保存收款码 → 用任意二维码识别工具读出里面的 URL。（也可以直接把保存下来的图片放进 `public/` 再改 `GET /api/alipay` 返回那个路径，但存成变量更好换。）

`SUPABASE_SERVICE_ROLE_KEY` 同样是必需的：账本对 `authenticated` 只授了 `select`，浏览器直连 Supabase 写不进去，这条路的写入也得走 service role。

## 本地试一遍

```powershell
# .env.local 里填上 ALIPAY_QR_URL 和 SUPABASE_SERVICE_ROLE_KEY
npm run dev
```

登录 → 设置 → 「用支付宝充值」→ 填金额（或点 ¥35 那个快捷键）→ 扫码付款 → 点「我已支付 ¥35」→ 面板上的账户余额应当立刻加 $5.00（¥35 ÷ 7）。

## 要真的计费，得先换掉什么

- **换成商户收款**：支付宝开放平台的 `alipay.trade.page.pay` / 当面付，需要企业主体、APPID 和 RSA2 密钥。有了它才有 `notify_url` 异步通知，钱到账才有客观依据。
- **幂等**：商户流程里用 `out_trade_no` 做唯一键，重复通知就撞唯一约束，跟现在 Stripe 那条路一样。
- **在此之前**，`POST /api/alipay` 不应该接到任何真正会扣减余额或解锁功能的逻辑上——它记的是一句自述，不是一笔款。
